医疗器械 B2B 大客户经营

可信数据、受控执行与评测回归

面向上三甲医院、区域医疗集团与经销商协同场景：先把医院、科室、设备、注册证与招采事实保存下来，再让 Agent 在授权范围内分析商机、核对资质并起草跟进，对客动作始终保留人工确认。

这是 young 的个人演示工作台。页面按真实业务结构搭建，使用虚构医院与商机数据，纯静态运行，不会调用真实模型，也不会对外发送消息。

要解决什么问题

医疗器械大客户经营周期长、角色多：院方企业微信、经销商群、招采平台与设备科拜访记录分散在不同渠道；注册证、UDI、授权链、EMC 报告和售后 SLA 又经常与具体投标项目绑在一起。客户偏好容易遗漏，资质材料可能过期，若让大模型直接承诺交期、价格或临床效果，还会带来合规风险。

系统的做法是：大客户经理选定医院或项目范围后，由 Agent 读取已确认的院方记忆、注册证与招采依据，分析商机并产出带来源、缺失材料和下一步建议的报告。临床评估、招采和合同推进由人工接续；对客消息、价格承诺与高敏写回必须经过独立确认，执行轨迹与评测回归用于定位事实遗漏和流程失败。

系统设计架构全景

将院方交互、受控 Agent Harness、注册与招采证据面、客户记忆和评测回归明确划界：记忆与知识摘要仅作参考，CRM 始终保留医院、设备、商机与合同事实，对客和高敏操作必须经过提案人审。

持久化 Run 与动作提案状态机

模型单回合结束只是中间态。异步队列、租约校验、6 字段带快照可逆写、人审挂起续跑与写回不确定停机共同保证长任务可控收敛。

核心能力

医疗主数据与权限隔离

把医院、科室、联系人、设备、商机、招采项目与合同能力封装为统一工具契约，入参强类型校验，并在入口绑定组织租户与角色权限。Agent 只能使用已发布白名单中的工具，跨医院查询遵守行级隔离和操作审计。

院方画像记忆

医院组织、设备装机、合同和招采事实保存在数据库中作为真源；科室采购偏好、预算边界、联系时间窗和沟通禁忌由长期记忆系统提炼。日常沟通增量写入，夜间清洗去重；临时项目偏好会衰减，院方联系窗口与合规约束则持久锁定。

注册与投标证据可追溯

NMPA 注册证、UDI、说明书、检测报告、授权链和售后 SLA 通过检索层读取，并校验资料白名单与项目授权范围。引用会记录内容指纹、证照有效期和文档版本；过期或未授权依据会被屏蔽，避免用旧证照或渠道授权参与投标。

长周期商机受控执行

大型设备商机往往跨越临床评估、院内论证、招采、合同与装机验收。系统用显式状态机把每回合拆成意图识别、资质校验、结果观测和副作用提议，任务队列负责续跑；满足业务验收条件后才进入终态。

临床、商务与资质交叉核验

对临床需求、设备交付可行性和招采资质合规性做并行只读分析，再交叉比对注册证有效期、授权链与项目字段。一旦发现资质缺失、报价越权或临床依据不足，就挂起自动推导，生成差异报告交由人工裁决。

评测与持续改进

用规则校验加上语义评审，覆盖医院范围查询、注册证引用、工具调用、招采审批、证据溯源和冲突识别。真实失败案例沉淀为回归集；改进链路只允许调整工具说明、专家分工、上下文装配和记忆召回，权限隔离与外发审批规则保持锁定。

人机协同与安全边界

  • 对客动作先提案、后确认 Agent 的写入和对客沟通只会生成提案，必须经大客户经理或销售主管确认后才落地，避免擅自修改招采阶段、价格承诺或直接发信。
  • 白名单写入与一键撤销 Agent 仅可自动修改 6 个低敏感运营辅助字段，写入前保存快照。人工撤销时会比对是否已被大客户经理改过，避免覆盖最新的人工修改。
  • 策略版本与紧急熔断 主管调整院方沟通策略时会生成新版本，并终止旧草稿继续执行。必要时可按全租户或单家医院立即阻断尚未发出的对客动作。
  • 审批防重与并发保护 批准、拒绝和暂停在重试时复用同一请求键，避免网络抖动导致重复执行；长耗时写入还会校验队列租约，拦截超时旧进程的迟到写回。

界面与工程

  • 流式执行时间线 工作台按事件顺序展示思考、工具调用和回执。页面刷新、断网重连或任务结束后再打开，都能完整回放执行过程。
  • 移动端与多端一致 界面适配软键盘和横幅高度，并处理中文输入法组合态。医疗设备商机看板用版本校验防止多端同时改写招采阶段时的脏更新。
  • 统一领域服务与异步执行 产品界面与 Agent 运行时共享同一套领域能力，数据层按组织做行级隔离。长任务先落库再入队，由独立 Worker 执行，避免页面超时悬挂。
